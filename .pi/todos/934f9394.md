**Goal:** Tiny subprocess adapter + readiness probe; lifecycle must not know agent/MCP semantics.

**File:** `src/webx/lifecycle.py` (RuntimeManager)

**Ops:** compose_up(), compose_stop(), compose_down(), compose_ps(), compose_logs(), probe_http(), ensure_running(), status(), doctor() helpers.

**ensure_running() algorithm (01 + 02 Phase3 + 04):**
1. probe GET {searxng_url}/ with httpx short timeout → if 2xx healthy return already_running=True without Docker
2. ensure templates exist (materialize if safe)
3. subprocess.run([docker, "compose", "-f", compose.yml, "up", "-d"], check, list args, no shell)
4. poll root URL until healthy or WEBX_STARTUP_TIMEOUT expires (configurable, default ~30s)
5. on timeout collect `docker compose logs --tail` for error context

**Other cmds (03):**
- `up` → ensure_running explicit
- `stop` → `compose stop`, idempotent success if already stopped
- `status` → JSON {initialized, docker_available, searxng_running, url, runtime_dir} with --json flag, human otherwise
- `doctor` → Python version, runtime dir, docker exists, compose version, templates present, loopback URL, SearXNG reachable, trafilatura/mcp versions; must NOT start SearXNG

**Tests:** Mock subprocess + httpx probe; verify already-running never calls Docker, stopped path calls up -d, polling success/timeout, stop idempotent, args are list not string.

**Risk:** SearXNG mount ownership (FORCE_OWNERSHIP) may require adjusting compose from single-file RO mount to dir mount; preserve 127.0.0.1 binding.

**Validation:** Manual `webx status` shows stopped; `webx up` starts; second `up` is fast.
